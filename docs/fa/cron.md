# راهنمای کرون (پردازش پس‌زمینه)

پیام‌ها ابتدا ذخیره و سپس از طریق صف به بله فرستاده می‌شوند. پس از ارسال هر پیام یک تلاش فوری و کوتاه انجام می‌شود، اما برای اطمینان، صف باید مرتب پردازش شود. کرون داخلی وردپرس فقط با بازدید از سایت اجرا می‌شود و قابل اتکا نیست.

## با WP-CLI (پیشنهادی)
```
* * * * * cd /path/to/wordpress && wp gapban worker --seconds=50 --quiet
```
در حالت دریافت دوره‌ای این خط را هم اضافه کنید:
```
* * * * * cd /path/to/wordpress && wp gapban poll --seconds=50 --quiet
```
تأخیر دریافت در حالت دوره‌ای حدود ۱ تا ۵ ثانیه است. تنها یک دریافت‌کننده هم‌زمان اجرا می‌شود.

## بدون WP-CLI (هاست اشتراکی، مثلاً cPanel/DirectAdmin)
در «راه‌اندازی ← پردازش پس‌زمینه» «ساخت نشانی کرون» را بزنید (فقط یک بار نمایش داده می‌شود) و در بخش Cron Jobs هاست اضافه کنید:
```
* * * * * curl -fsS -m 55 -X POST 'https://example.com/wp-json/gapban/v1/cron/رمز' >/dev/null
```

## خاموش کردن کرون داخلی وردپرس (اختیاری)
وقتی کرون سرور فعال شد، می‌توانید در wp-config.php بنویسید: `define( 'DISABLE_WP_CRON', true );`

## سایر فرمان‌ها
- `wp gapban status` — وضعیت ربات، وب‌هوک و صف
- `wp gapban maintenance` — اجرای فوری پاک‌سازی
- `wp gapban rotate-key` — رمزنگاری دوبارهٔ رمزها با کلید جدید
